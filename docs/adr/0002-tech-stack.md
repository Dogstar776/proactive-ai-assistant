# ADR-0002：技术栈选型

- 状态：已接受（2026-10-17，P0 确认）
- 背景：单开发者（维护者）个人项目，同时处于求职转型期，时间碎片化；需要 AI 生态友好、工程规范可展示、本地零运维。

## 决策

| 层 | 选择 | 一句话理由 |
|---|---|---|
| 后端 | Python 3.11+ / FastAPI | 单开发者最快、类型提示、异步、AI 生态无缝；巩固维护者在学的 Python |
| 结构化存储 | SQLite（WAL 模式） | 本地优先零运维；个人尺度无需 PostgreSQL；数据主权物理可控 |
| 向量存储 | ChromaDB | 本地嵌入检索，与 SQLite 同机部署，无外部服务 |
| 前端 | React + TypeScript + Vite | 生态成熟；维护者设计审美（浅色简约）有发挥空间；作品集成份 |
| 通信 | REST + SSE | REST 管资源；认知环事件流用 SSE 单向推送足够，免 WebSocket 复杂度 |
| 部署 | 本地单用户，绑定 127.0.0.1 | v0 无鉴权系统；单人助理无多租户需求；远程访问留待真需要时加 token |
| LLM | Provider 抽象（OpenAI 兼容 / DeepSeek / Ollama 可插拔），默认 MockLLM | 无密钥完整复现是开源项目的基本礼仪；模型当可替换部件，不绑定厂商 |
| 测试 | pytest（后端）/ vitest（前端） | 与框架默认生态一致，CI 接入成本最低 |

## 被否决的备选

- **Django**：功能全但重，ORM 与异步支持对单人项目是负担；
- **PostgreSQL + pgvector**：运维成本与个人尺度不匹配，SQLite + Chroma 已覆盖；
- **Next.js 全栈**：把前后端耦合进一个框架，不利于论文要求的"分层可检验"工程表达；
- **WebSocket**：认知环是单向广播语义，SSE 更简单且自带重连讨论空间；
- **localStorage 存任何凭证**：专家规范红线，本项目 v0 干脆不设凭证。

## 后果

- 正面：任何人 `git clone` 后MockLLM 模式可跑；工程规范（分层/类型化错误/结构化日志）可直接写进简历与面试；
- 负面：SQLite 在高写入下有上限（本项目日级写入量远低于）；前端工程量是后端 1.5–2 倍；
- 后续观察：若 P6 实验需要多设备同步，再评估轻量 token 鉴权 + 局域网部署。
