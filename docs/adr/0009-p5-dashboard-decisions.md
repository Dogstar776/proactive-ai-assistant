# ADR-0009：P5 仪表盘的工程决策

- 状态：已接受（2026-10-17，P5 实施）
- 背景：P5 是 demo 的"脸"——认知环可视化 + charter 编辑器 + 提醒台账。视觉基调由维护者指定：Apple iOS 26 Liquid Glass（浅色、层叠半透明、高光边缘、弹簧动效），"简约高级但功能不阉割"。

## 决策一：七个视图 = 论文五层 + 两个基座，一个不少

认知环 / 事件流 / 自省 / 目标 / 提醒门控 / Charter / 成本。每个视图直接对应后端一类端点，
不做"演示专用简化版"——仪表盘即控制台，功能与 API 1:1（维护者原话：功能不阉割）。

## 决策二：沉默必须可见

提醒台账把 `status=suppressed` 的条目与原因（quiet_hours / cooldown / daily_budget）
与 delivered 同级展示。ADR-0008 的"可审计的沉默"在 UI 侧的落实：用户能亲眼看到
"系统今天为我沉默了 5 次，分别是为什么"。

## 决策三：charter 编辑器直写 data/charter.yaml + 热重载

编辑器保存 → 后端校验 YAML → 写配置的 data_dir（不是相对路径，见下方事故记录）→
清服务缓存热重载。charter 是 Git 版本管理的文本文件，UI 只负责降低编辑门槛，
不引入第二份真相。

## 决策四：错误边界 + 空字段防御

单视图崩溃不得白屏全应用（ErrorBoundary）；API 字段缺失时前端防御性取值。
**事故记录（2026-10-17 浏览器实测）**：后端序列化漏了 `content` 字段，事件流视图
`ev.content.slice()` 抛 TypeError 整个应用白屏。修复：后端补字段 + 前端空值防御 +
错误边界兜底。教训：**浏览器实测不是可选项**——单测全绿 ≠ 页面不崩。

## 决策五：vite 代理纯转发

前端路径与后端路由完全一致（/health、/ready、/api/v1/*），proxy 不做 rewrite。
曾试过 `/api` 前缀重写，反而把 `/api/v1/*` 改错——路径设计一致时最简单。

## 已知局限

- SSE 断线重连由浏览器 EventSource 自动完成，未做指数退避定制；
- 免打扰展示用 charter 字面量，未在 UI 标注时区（后端已修 UTC/本地错位）；
- 移动端适配做了响应式断点，但未做触屏专项测试。
