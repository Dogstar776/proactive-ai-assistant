# ADR-0008：P4 对齐层与提醒引擎的工程决策

- 状态：已接受（2026-10-17，P4 实施）
- 背景：P4 落地论文 3.5（人机可控安全对齐层）与 1.2.5（Tang et al. 主动服务 Agent 的沉默-干预理论）。

## 决策一：四态判决顺序 = 沉默条件优先于放行条件

免打扰 → 冷却 → 每日预算 → 风险分级（R3 ask / R2 assist / R1 act / R0 act）。
**理由**：论文 3.5 的"超时策略=默认不行动"意味着门控的默认偏置是沉默；把三个沉默条件放在风险分级之前，保证任何资源/时间约束都能一票否决。
**后果**：一次"放行"需要同时通过全部四道检查；每道检查失败都产生不同 reason，审计日志可归因。

## 决策二：沉默也是显式记录，不是"什么都不做"

silence 判决写入 reminders 表（status=suppressed）+ gate.decision 审计。
**理由**：论文 4.5 指出监督注意力稀释是结构性的——如果沉默不留痕，人类无法区分"系统认为不该说"和"系统坏了没说话"。可审计的沉默是抗授权疲劳的信息基础。

## 决策三：关键词风险分类器过度保守，且失败方向安全

分类器扫描标题+正文的高/中/低风险词。已知局限：不理解否定语义。
**事故记录（2026-10-17 冒烟）**：模板免责声明"不对外发送"命中"发送"、不自动删除任何原始记录"命中"删除"，两个只读目标被误升 R3。修复：模板措辞避开词表 + 回归测试 `test_readonly_template_drafts_stay_r1` 锁死三个模板的措辞。
**保留理由**：误判方向是"只读目标被挂起请示"——门控系统漏放行好于误放行。这与论文 5.1 表 2 把"内生行为风险分级"判为 B 级的判断一致：我们做初筛，不假装可靠。

## 决策四：提醒 ID 按（冷却键，日期）生成，当日可刷新

同一目标同一天重复跑周期 → INSERT OR REPLACE 刷新状态（如从 suppressed 变 delivered），跨天自然生成新记录。
**理由**：提醒是"当天意志"的表达，不是永久事实；审计日志保留全天判决历史。

## 决策五：触达渠道只做 SSE，不谎称本地通知

README 与文档明确：本地系统通知（Windows toast）未实现即不写。P5 仪表盘落地后按需补充。
