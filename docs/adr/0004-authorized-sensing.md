# ADR-0004：授权持续感知与数据主权

- 状态：已接受（2026-10-17，P0 确认）
- 背景：用户原始表述为"AI 无感收集用户多类信息"。论文 P5 把授权定义为硬约束；公开仓库出现"无感收集"表述构成伦理与声誉负资产；2026-10 市面调研显示记忆孤岛与 GDPR 争议正是当前最大痛点（ChatGPT Dreaming 欧盟被封锁）。

## 决策

1. **术语**：全仓库（README/代码注释/文档/UI）统一使用"**授权持续感知**"，禁用"无感收集"；
2. **consent ledger（授权账本）**：每次采集记录来源、范围、时间、授权 ID，用户可在仪表盘查看与撤回；
3. **本地优先**：SQLite/ChromaDB 落本机 `data/`，无云端同步、无遥测、无导出通道；单用户（维护者本人）即数据主体；
4. **全量审计日志**：门控决策（放行/挂起/熔断）与授权请求全链留痕，支持事后审计（论文 3.5）；
5. **provenance 溯源**：每条记忆标记来源（用户注入/系统回写/外部检索）与生成链深度，服务 OQ4 指标；
6. **第一版信息源**（三类，本地）：日程/待办（ICS 与 Markdown）、笔记文件夹（Markdown）、RSS/信息流；邮件与浏览器历史暂不纳入（隐私争议与工程量均上一量级）。

## 理由

- 论文 5.4.3 指出个人/边缘级算力的独特优势即数据主权——本项目把该优势做成显性设计而非口号；
- MemoryLake/Hatch 等第三方记忆层产品（见调研文档）证明"用户自持记忆"是真实市场需求方向；
- 授权账本本身即是 P5 的工程证据，比任何宣传话术都可信。

## 被否决的备选

- **"无感收集"原表述**：与论文 P5 冲突，公开社区一票否决；
- **邮件/浏览器历史入库**：信息类型更全，但采集面越界、授权粒度难做细，留待 P6 后评估；
- **云端同步（自建或第三方）**：破坏数据主权主张，且引入密钥管理复杂度。

## 后果

- 正面：伦理站位清晰；审计日志成为作品集里"懂对齐"的硬证据；
- 负面：功能广度让位于采集边界，"多类信息"第一版只有三类；
- 后续观察：授权撤回功能（ledger 支持 disable）在 P4 实现，作为 P5 门控的对称设计。
